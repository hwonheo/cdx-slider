# 설치 안내

[English](Installation.md) · [문서 목록](../README.md)

## 설치 전 준비

**Node.js 22.13 이상**과 플러그인을 지원하는 Codex가 필요합니다. 저장소 복제를 위해 Git도 준비하세요. 패널 UI를 사용하려면 Codex 호스트가 MCP Apps를 지원해야 합니다.

터미널에서 다음 명령으로 설치 여부를 확인하세요. Node.js 버전은 22.13 이상이어야 합니다.

```sh
node --version
npm --version
git --version
codex --version
```

macOS에서 Slider Bar까지 설치하려면 Swift 명령행 도구도 필요합니다. `swift --version`으로 확인하세요. 미니바 없이 설치할 경우 아래 준비 명령 끝에 `--without-companion`을 추가하세요.

## 저장소 복제 및 플러그인 준비·활성화

터미널에서 저장소를 복제하고 해당 폴더로 이동한 뒤 실행하세요.

```sh
git clone https://github.com/hwonheo/cdx-slider.git
cd cdx-slider
npm ci
npm run build
node scripts/stage-plugin.mjs "$HOME/plugins/cdx-slider"
```

마지막 명령은 MCP 서버·스킬·패널·문서가 포함된 별도 폴더를 준비합니다. macOS에서는 Swift 명령행 도구로 Slider Bar도 빌드하여 준비 폴더에 설치하고 실행 감시를 등록합니다. 앱은 이 고정 경로에서 실행되므로 준비 폴더를 유지하세요. 플러그인 자체를 등록하거나 활성화하지는 않습니다. 미니바 없이 설치하려면 준비 명령에 `--without-companion`을 추가하세요.

Codex에서 사용 가능한 `$plugin-creator` 스킬에 “준비된 cdx-slider 폴더를 개인 마켓플레이스에 등록하고 로컬 플러그인으로 설치해줘”라고 요청하세요. 준비 명령이 출력한 절대 경로를 전달하고 호스트의 설치 절차를 완료한 다음, 새 작업을 열어 도구와 스킬을 불러옵니다.

설치용 설정에는 Node와 서버의 절대 경로가 기록됩니다. 폴더나 Node를 이동하면 다시 준비·설치하세요. 이 폴더를 다른 컴퓨터에 그대로 배포하지 말고 대상 기기에서 빌드·준비하세요.

## 저장하고 이어가기

1. 새 작업에서 `$cdx-slider:slider-continuity`를 실행합니다. 패널 열기만 요청합니다.
2. 첫 사용 시 패널에 표시되는 **저장용 프로필 만들기**에서 이름과 ID를 입력합니다. 생성한 프로필은 즉시 선택되고 프로젝트 등록 양식이 열립니다. 이후에는 **프로젝트 등록**을 사용합니다. 저장 프로필은 Codex 계정과 별개인 작업 보관용 이름입니다.
3. 프로젝트를 선택하고 **현재 대화 저장**을 누릅니다. 에이전트가 체크포인트 저장 성공을 확인할 때까지 기다립니다.
4. 프로젝트 폴더에 접근할 수 있는 새 작업에서 패널을 열고 **마지막 작업 불러오기**를 누릅니다.

다른 저장 프로필을 사용하려면 먼저 해당 프로필에 프로젝트 공유를 명시적으로 요청하세요. 계정 전환은 Codex에서 직접 수행합니다. 전환 후 플러그인이 보이지 않으면 해당 환경에서 다시 활성화하세요.

MCP Apps를 지원하지 않는 호스트에서는 패널 리소스 반환만으로 화면이 표시되지 않습니다. 스킬에 저장·불러오기를 직접 요청하거나 [CLI](Function.Details.ko.md#cli)를 사용하세요. 실제 호스트 검증은 [수용 테스트](acceptance.ko.md)를 참고하세요.

## macOS 미니바 수동 설치·복구

위 준비 명령을 사용했다면 별도 설치는 필요하지 않습니다. macOS와 Swift 명령행 도구가 필요합니다. 개발 저장소에서 미니바만 수동으로 설치할 때 실행하세요.

```sh
npm run build:companion
npm run install:companion
```

`dist/CDX Slider.app`을 빌드하고 실행 감시를 등록합니다. Codex 실행 시 미니바가 표시됩니다. macOS 로그인 항목에 중복 등록하지 마세요. 감시 등록 해제:

```sh
npm run uninstall:companion
```

앱과 저장된 프로젝트 데이터는 유지됩니다. [미니바 동작과 중계 제한](Function.Details.ko.md#macos-미니바)을 확인하세요.

## 설치 제거

### 한 번에 제거 (기본 개인 설치)

복제한 저장소에서 다음 한 줄을 실행하세요.

```sh
npm run uninstall:all
```

Slider Bar를 종료하고 자동 실행 등록, `cdx-slider@personal` 플러그인, 기본 준비 폴더 `~/plugins/cdx-slider`, 개발 빌드의 `dist/CDX Slider.app`을 제거합니다. 저장소 소스와 저장된 프로필·메모리·체크포인트는 보존합니다. 다른 경로·마켓플레이스로 설치했다면 아래 개별 제거 절차를 사용하세요. 마켓플레이스의 설치 가능 목록 등록은 남을 수 있습니다.

실행 없이 정리 대상을 미리 확인하려면 `npm run uninstall:all -- --dry-run`을 사용하세요. 제거 전 저장·복원을 마치고, 제거 후 기존 플러그인 작업을 닫아 남은 연결을 정리하세요.

### 개별 제거 및 데이터 삭제


진행 중인 저장·복원 작업을 마친 뒤 아래 순서로 제거하세요. 기본 제거는 저장용 프로필, 프로젝트 등록, 메모리와 체크포인트를 보존합니다.

1. **macOS Slider Bar 중지 및 자동 실행 해제**: 복제한 개발 저장소에서 실행합니다. 준비된 플러그인 폴더에는 이 npm 스크립트가 없습니다.

   ```sh
   npm run uninstall:companion
   ```

   개발 저장소가 없다면 터미널에서 다음을 실행하세요. 첫 명령이 이미 등록되지 않았다는 오류를 내면 plist 파일만 제거하면 됩니다. 그 밖의 권한 오류는 해결한 뒤 진행하세요.

   ```sh
   launchctl bootout "gui/$(id -u)/local.cdx-slider.companion"
   rm -f "$HOME/Library/LaunchAgents/local.cdx-slider.companion.plist"
   ```

   수동으로 실행한 미니바가 남아 있으면 앱 메뉴의 Quit으로 종료하세요. 자동 실행만 해제하려면 여기서 멈추세요. 이후 macOS에서 준비 명령을 다시 실행하면 자동 실행도 다시 등록되므로, 유지하려면 `--without-companion`을 사용하세요.

2. **Codex 플러그인 제거**: 기본 개인 마켓플레이스 설치 기준입니다. 다른 마켓플레이스로 설치했다면 `personal`을 해당 이름으로 바꾸세요.

   ```sh
   codex plugin remove cdx-slider@personal
   ```

   설치 캐시는 제거되지만 원본 준비 폴더와 저장 데이터는 남습니다. 기존 작업에 연결된 도구가 남아 있으면 해당 작업을 종료하고 새 작업에서 확인하세요. 별도로 MCP만 등록했던 경우에만 `codex mcp remove cdx-slider`를 사용하세요.

3. **선택: 앱·준비 폴더 정리**: 기본 경로인 `~/plugins/cdx-slider`를 Finder에서 휴지통으로 옮기면 그 안의 Slider Bar도 제거됩니다. 다른 경로로 준비했다면 실제 설치 경로를 확인하세요. 개발 저장소의 `dist/CDX Slider.app` 사본은 별도입니다. 개인 마켓플레이스의 등록 항목이 남아 있으면 설치 가능한 목록에는 계속 보일 수 있습니다. 다른 플러그인이 사용하는 마켓플레이스 전체를 삭제하지 마세요.

4. **선택: 저장 데이터까지 완전히 삭제**: 모든 Slider Bar와 이 플러그인을 사용하는 작업을 종료한 뒤, 필요한 데이터를 백업하고 `~/.local/share/cdx-slider` 폴더를 휴지통으로 옮기세요. `CDX_SLIDER_HOME`을 지정했다면 해당 경로가 실제 저장 위치입니다. 모든 저장용 프로필의 메모리·체크포인트와 프로젝트 등록이 삭제되며, 등록된 프로젝트의 원본 파일은 삭제되지 않습니다. 재설치 후 이어서 쓰려면 이 폴더를 보존하세요.

## MCP만 등록하기

로컬 MCP는 지원하지만 위 플러그인 설치 흐름을 사용할 수 없는 환경에서는:

```sh
codex mcp add cdx-slider -- node /absolute/path/to/cdx-slider/dist/server.mjs
```

경로를 빌드한 저장소의 실제 위치로 바꾸세요. MCP 서비스만 등록되므로 스킬은 별도 설치해야 합니다. 플러그인과 MCP를 중복 등록하지 마세요.

## 업데이트

업데이터가 포함된 버전을 설치한 뒤 macOS 메뉴 막대의 **CDX → 업데이트 확인…**에서 정식 릴리스를 확인하고 설치할 수 있습니다. **CDX → 자동 업데이트 설치**를 켜면 자동 설치하며 기본값은 꺼짐입니다. Codex와 미니바가 실행 중일 때 시작 시점과 이후 주기적으로 확인하며, 자동 시도 간격은 최소 6시간입니다. 미니바를 종료하면 정기 확인도 중단됩니다.

`hwonheo/cdx-slider`의 정식 `vMAJOR.MINOR.PATCH` 릴리스만 설치합니다. 개발 커밋을 푸시할 때마다 사용자 설치가 바뀌지는 않습니다. 내보낸 파일의 체크섬을 검증한 뒤 임시 폴더에서 빌드하고 플러그인과 미니바를 함께 교체합니다. Node.js 22.13 이상, npm, Git, 미니바용 Swift 명령줄 도구가 계속 필요합니다. 개인 마켓플레이스가 준비된 설치 폴더를 참조해야 하며, 별도 마켓플레이스나 Git 마켓플레이스 설치는 이 로컬 업데이터의 대상이 아닙니다.

설치 후 미니바는 재시작됩니다. 새 Codex 작업을 열고, 이전 플러그인이 계속 로드되어 있다면 Codex를 직접 재시작하세요. Codex 자체를 자동 재시작하지는 않습니다. 저장된 프로젝트와 체크포인트는 기존 데이터 폴더에 유지됩니다.

소스 저장소에서도 제어할 수 있습니다.

```sh
npm run update -- status
npm run update -- check
npm run update -- apply
npm run update -- auto-on
npm run update -- auto-off
```

기본 대상은 `$HOME/plugins/cdx-slider`입니다. 다른 경로는 명령 마지막에 설치 폴더의 절대 경로를 추가하세요. `auto-on`은 미니바의 정기 확인을 켜며, 미니바가 없는 환경에 별도 상시 스케줄러를 설치하지 않습니다. 기존 설치에는 업데이터를 받기 위한 수동 빌드·준비·플러그인 재설치가 한 번 필요합니다.

일반적인 설치 실패 시 이전 설치본으로 복원하고 다시 실행합니다. 교체 중 프로세스나 컴퓨터가 종료되면 복구 파일을 보관하고 후속 업데이트를 차단합니다. 소스 저장소에서 `npm run update -- recover`를 실행해 복원·재활성화하세요. 재활성화도 실패하면 이전 파일은 유지되므로 오류를 확인한 뒤 재시도하세요. 상태·진단 로그·복구 기록은 `$CDX_SLIDER_HOME/updates`에 있으며 기본 경로는 `~/.local/share/cdx-slider/updates`입니다. 체크섬은 파일 변조·손상을 검출하며, 배포자 신뢰는 별도 서명 키가 아닌 HTTPS와 공식 GitHub 저장소 관리에 기반합니다.
